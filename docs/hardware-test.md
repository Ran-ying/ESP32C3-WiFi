# 实机验收（待人工执行）

不将未执行的步骤记为 PASS。请只使用自己的 WPA2-Personal + CCMP 路由器。关闭自动信道与 WPA3 过渡模式，2.4 GHz 固定 CH1。

1. 记录串口中的设备热点密码，iPhone 加入 ESP32C3-Auditor，Safari 打开 http://192.168.4.1 。如提示无互联网，保持加入该网络。
2. 确认显示 AP、IP、实际 CH1。勾选授权，点击被动扫描；按 BSSID 区分同名 SSID。
3. 选择自己的测试 BSSID。先看到切换通知，再发生断线；重新加入同一个 ESP32 热点，打开相同地址。实际信道应与目标一致，MCU 不重启。
4. 将测试路由器改为 CH6，再扫描、选择、重连；随后重复 CH11，最后重复 CH1。记录实际信道、重连耗时、异常及启动计数。不能只根据 UI 的目标信道判定成功。
5. 扫描期间监听必须暂停。路由器自动换信道后需要重新选择。ESP32 的 AP 信标和手机网页流量仍存在；“被动”指不干扰目标网络、STA 不连接目标。
6. M2/M3 步骤将在实现后补充；使用另一台自己控制的终端正常加入测试路由器，手机可继续留在 ESP32 热点。

设备不会发起 deauth/disassoc 或强制任何终端重连。

## M2 与 M3

1. 选择自己的固定信道 WPA2-PSK + CCMP 测试网络，重新加入设备热点。确认实际信道与目标一致、监听中、数据帧计数增长。
2. 用另一台自己控制的终端正常加入测试路由器；必要时由你手动关闭/开启该终端 Wi-Fi。设备不会诱导或强迫重连。iPhone 可保持在 ESP32 热点查看捕获。
3. 记录每个客户端的 M1/M2/M3/M4、CAPTURED/VERIFIABLE/COMPLETE、丢帧与覆盖。缺少任意验证字段时，“开始”必须禁用。没捕到 M1 但有可关联的 M3+M2 可显示 VERIFIABLE。
4. 分别导出 PCAP 和结构化 JSON，只存私有位置。用 Wireshark 检查 radiotap 的接收信道与 802.11 BSSID、EAPOL 长度及消息，不公开实网握手。
5. 手机本地建立小 TXT 字典：至少一条 8–63 字节错误候选和测试路由器的已知密码。点击加载捕获、选择会话和 TXT，再开始。必须只在正确候选处显示匹配；错误字典完成后应显示未找到。
6. 较长字典验证暂停、继续、停止；Safari 主界面应可操作。刷新后匹配结果消失。不得把字典或实际密码提交 Git。
7. CH1、CH6、CH11 各自完成重新扫描/选择/重连，检查启动标识不变、运行时间持续增长（正常切换不重启 MCU）。当前俄罗斯配置额外支持 CH12/13，但未经实测不得报告 PASS。
